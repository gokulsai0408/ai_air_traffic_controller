A safer way to decide when flights unravel

When a storm hits a hub, air traffic control, the airline and the ramp each fight their own clock. AirSync lets three AI agents negotiate a fix in seconds, has deterministic code check every plan for safety, and puts the final call with the airline's duty manager.

The problem

One storm creates three competing clocks

A thunderstorm cuts the arrival rate at a hub. A delayed flight is inbound, its gate may be taken, the crew is near its duty limit and passengers have tight connections. Each organisation optimises its own piece.

Runway

  • Arrival rate falls
  • Wake separation still applies
  • Controllers need a workable slot

Aircraft

  • Fuel margin shrinks
  • Crew duty time keeps running
  • Passengers risk missed connections

Gate + ramp

  • Original gate may be occupied
  • Taxiways can close
  • Ground shift has an end time

Today these teams reconcile the picture by phone and radio. In our scenarios the first-come-first-served plan was unsafe 73% of the time modelled

How it works

Two rounds, then a safe outcome

A non-AI coordinator runs a fixed protocol with a hard two-round cap, as the brief's "under three turns" asks. The loop can never run forever.

1

Disruption

A real delayed flight plus generated airport context and ops notes.

2

Options

Concrete plans from the menus: runway slots, gates, holds and diversions.

3

Safety check

Pure code removes every unsafe plan before anyone votes.

4

Agents negotiate

Each agent proposes, assesses with its own costs and votes with a reason code.

5

You decide

The duty manager approves, overrides with another safe plan, or rules on an exception.

The design rule

AI argues. Code decides.

Language models are good at reading messy text and explaining themselves. They can't be trusted with arithmetic or legality, so they never get it.

What the AI agents do

  • Read free-text ops notes into a fixed, restrict-only format
  • Propose plans from the menus, never invented IDs
  • Vote on the shortlist with a reason code and a short rationale
  • Explain their position to the duty manager

What code does

  • All arithmetic: times, fuel, delay, costs
  • All legality: 12 numbered constraints, each with a source
  • When to stop: round cap, binding compromise, fallback, escalation
  • The audit log, and replaying it without any AI

Features

Built for a duty manager who has to trust it

Three independent agents

ATC, pilot / airline and ground ops are three separate AI calls with their own prompts, private data and costs.

Deterministic safety kernel

Runway, wake separation, fuel, crew duty, gate size, gate conflicts and taxiways, checked by pure code every time.

Human in control

Approve, override with another kernel-checked plan, or approve a single company-policy exception. Safety limits are never relaxed.

Says no when it should

When nothing is safe it refuses, names the blocking constraint and the person who must act.

Private data stays private

Agents share only a cost and a reason code per plan, never fuel figures, crew hours or passenger counts.

Tamper-evident audit log

Every step is hash-chained. Verify replays any run without calling an AI, and a one-byte edit is caught.

Prompt-injection resistant

Free text can only add restrictions. An injected “ignore the fuel reserve” has nowhere to go.

Data

Not a trained model.

AirSync doesn't train or fine-tune anything. The agents use Claude as-is for reading and arguing, and every number comes from deterministic code over the data below. Synthetic values are generated by a seeded generator, so the same flight and seed always give the same world.

Honest limits

Where it can fail, and how you'd know

  • Synthetic airport context. Gates, fuel and crew are generated; results that depend on them are labelled modelled.
  • Self-reported costs. An agent that lies about its own cost could steer the outcome. Stated openly; the fix is mechanism design or audit.
  • No delay reduction claimed. In this model every plan takes the earliest legal slot; the gains are safety and cost, not minutes.
  • Simplified rules. Wake and fuel checks are simplified versions of the real procedures.

Built with

Small, testable, reproducible

  • Python with pydantic contracts for every message between components
  • Claude through the Anthropic SDK, with structured output and a retry-then-rule-agent fallback
  • Streamlit dashboard for the duty manager
  • 562 automated tests, a hash-chained ledger and a verify command that replays runs without AI
